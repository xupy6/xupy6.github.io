# Skills 更像是给自己留操作手册

最近在整理一些可复用的前端风格和开发流程，发现 Skill 这种东西不能写得太玄。

我一开始会想把所有规范都塞进去：颜色、动效、组件、文件结构、命名方式、交互细节。后来发现这样反而不太好用，因为真正开始写代码时，最需要的是几条能直接影响决策的规则。

比如做液态玻璃风格时，最有用的不是“高级、苹果味、柔和”这种词，而是更具体的东西：

- 大面积留白，但内容区不能太窄。
- 卡片可以透明，但层级之间要有对比。
- 按钮不要纯灰，要有一点非常淡的渐变。
- 动效要短，不能为了动而动。
- 音乐播放器这种组件要先满足真实使用，再谈装饰。

这些东西写进 Skill 后，下次做类似页面就不会从零开始找感觉。它更像是自己的手感记录，而不是通用教程。

我觉得好的 Skill 应该有一点“偏心”。它不是告诉模型所有可能性，而是告诉它我更喜欢哪一种实现，以及哪些坑我已经踩过。
