# Agent 编排先把状态想清楚

这段时间写 Agent 流水线，最大的感受是：不要一上来就把图画得很复杂。图看起来高级，但真正让系统能跑起来的是状态设计。

我现在会先把状态拆成几类：

- 输入：用户原始材料，尽量不改。
- 中间结果：每个节点只写自己负责的字段。
- 诊断信息：模型返回异常、解析失败、耗时、重试次数。
- 最终结果：前端真正会展示的结构。

这个习惯能少很多麻烦。以前我会让 Agent 之间互相传一大段文本，后面调试时根本分不清是谁把信息弄丢了。后来改成每个节点只更新明确字段，问题会直观很多。

并行节点也不是越多越好。并行适合彼此真的没有依赖的任务，比如语言风格、情绪统计、互动频率。只要某个节点需要读另一个节点的输出，就不要硬并行，不然最后还是要补一堆等待和兜底逻辑。

还有一个小经验：Agent 输出最好从第一天就要求 JSON schema。哪怕模型偶尔会吐废话，也比后面再从自然语言里抠字段强。工程里最难受的不是模型错，而是错得没有固定形状。
