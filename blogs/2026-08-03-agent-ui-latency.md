# 做可交互 AI 产品时，等待感要被设计

Agent 应用和普通表单不太一样。普通请求几百毫秒到一两秒就结束，用户还能接受一个简单 loading。Agent 链路经常要解析、检索、调用模型、合并结果，等待时间一下就变得很明显。

我以前会直接放“分析中...”，后来发现这会让页面显得很空。用户不知道系统卡住了还是还在跑，也不知道下一步会发生什么。

现在我会把等待拆成几个阶段：

- 上传完成：让用户知道文件已经接住了。
- 解析中：告诉用户系统在读内容。
- 分析中：显示一个会慢慢推进的进度条。
- 生成报告：最后阶段可以慢一点，但不能停在原地。

进度条当然不一定是真实后端进度，很多时候是前端模拟。但它不能太假。比如 95% 之后应该变慢，到 99% 等后端结果；结果回来再到 100%。这个细节很小，但体验差别很大。

AI 产品的等待不是技术问题，也是信任问题。用户愿意等，是因为他感觉系统真的在做事。
